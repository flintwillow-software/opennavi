## [Unreleased]

### Added
- M6 — synthetic out-of-repo CI modules (NAVI-346): `tools/external-component` is its own module publishing a tool, a connector, and a fail-closed portal that import **only** the public contract packages (`tool`, `thought`, `connector`, `portal`, `model`, `skill`), and `tools/external-navi` is its own module composing the public `navi` root over that component and validating it. The CI guardrail builds and runs both and asserts the component's import boundary — its direct imports must be public contract packages, and its dependency closure must not reach `navi` or `internal/` — so an extension author outside this repository provably needs nothing but the public surface
- M5 — the reference navi and the starter templates (NAVI-347). `cmd/navi run` now assembles through `navi.New` instead of `internal/daemon.Assemble`: the reference navi builds durable stores, the full catalog, configured providers (with the ADR 0009 fallback chain and `--compact-budget` compaction), the cron connector, and its portals, then calls `navi.Run`. `enqueue`/`health` are unchanged; daemon mode additionally serves the HTTP portal gateway, and the gateway is now a real control surface — the public `portal.Control` + `portal.Authorizer` let remote front-ends attach, observe, and control (queue, steer, pause/resume/cancel, bump, retry) across processes. `portal/tui` is public and `internal/portal/cli` (the legacy REPL) is deleted: the default command runs the navi (TUI, or headless with `--daemon`). `navi-code` and `navi-daemon` are converted to real `navi.New` modules (no `sdk.Build`). NAVI-353 tracks transcript replay/restore across all portals; NAVI-354 tracks the daemon-run-path cleanup

### Removed
- M6 — the `sdk/` authoring stub (NAVI-346): `sdk.NaviDef` and `sdk.Build` are deleted now that the `navi` object owns authoring (M5), and the synthetic `tools/sdk-consumer` module that imported them is retired. Its replacement keeps a distinct CI check: the `templates` job (S000805 guardrail) is unchanged, and a new `external-consumer` job builds and runs the two external modules and asserts the component's import boundary

- Thought system promoted to public (M3, NAVI-348): `internal/thought` becomes `thought/`, merged with the M1 contract that was waiting for it, and the navi's type-translation bridge is **deleted** — it existed only because two type universes coincided, and now there is one (59 files, +755/−1209: a net deletion). One `Thought` (runtime fields plus the contract's `Mode`), one `ThoughtStatus` (the contract's `Status string` was a placeholder), one event type (`QueueEvent`/`QueueEventKind` become `Event`/`EventKind`; `EventPaused` absorbs `EventPausedEv`; `EventDeleted` and `EventPersistFailed` come along). `ThoughtQueue` becomes `Queue`. **Components get `ThoughtSystem`: control and reporting only** — the concrete `*Queue` carries the runtime hooks (`Dequeue`, `PauseWithCheckpoint`, `RouteMessageWithPath`, `Slots`, `StartFlusher`, `StartReconcile`, `SetSteeringRouter`), so a component can neither take work off the queue nor construct the agent's serialized checkpoint, and a compile-time assertion pins the narrowing. `Pause(id)` and `RouteMessage(id, text) error` are the contract forms; the checkpointed park and the delivery path moved to the concrete type. `Thought` gains `Result` — the completion message, persisted via migration 9 and round-tripped including the empty and failed cases — with `Complete(id, result)` and `Fail(id, detail)` joining the handle, since reporting an outcome is not claiming work. **One behaviour change:** `Enqueue` now treats an empty status as pending, because deleting the bridge removed the only thing that defaulted it and restating the queue's entry condition is a trap rather than a check; enqueueing in any *other* state is still an invalid transition. **Interface set retired in code** (ADR 0010): the selection machinery (`Interface`, `Constructor`, `Registry`, `Select`, `RunAll`, `InterfaceSet`, `InterfaceConfig` and their tests, ~330 lines) is deleted — its only purpose was to unify surfaces and transports, which ADR 0010 resolved into two layers, and its registry had no callers outside its own package. `internal/interfaces` becomes `internal/portal`. The control plane is renamed `Hub` and documented as a shared *service* (bounded mailbox fanout + authz) rather than a front-end, and satisfies `portal.Portal` so the composition root can register it; front-ends (TUI, gateway) still attach to it because the contract cannot yet feed them observation — tracked as **NAVI-352**. Docs reconciled (`runtime.md`, `overview.md`); the queue is no longer described as private mechanics. No change to the existing daemon path beyond the added `NAVI_PROVIDER`
- Provider slice (NAVI-343): models are now declarable, selectable, and runnable. `model/` gains `Ollama`/`OpenRouter` descriptor constructors with `WithEndpoint`/`WithCredential`/`Default`, and `Provider` carries `Credential` — a **reference** (env var or file name), never a value (ADR 0008), because descriptors get logged, echoed in tool output, and committed — plus `Mode` and `Default`; compiled endpoint defaults live in the binary and the operator overrides them at runtime. `internal/provider` binds a descriptor to a live adapter, resolving credential references from the environment **fail-closed**, with an error that names the reference and never the value, caching the result, and erroring loudly on an unknown name instead of falling back silently (ADR 0009). The navi resolves its default through the override chain **env (`NAVI_PROVIDER`/`NAVI_MODEL`) > config file (`provider.primary`/`.model`) > build time (`model.Default()` or `WithDefaultModel`)**, recording which layer decided; the config file is read **raw rather than merged**, because `DefaultRuntimeConfig()` bakes in ollama and merging would let that baked value outrank the compiled default; the model's build-time fallback follows the *selected* provider, so retargeting a provider does not drag the previous provider's model along; a blank env var is not an override; and the default resolves fail-closed at `Run` so a navi never accepts work it could not complete. `NAVI_PROVIDER` is new and mirrors `NAVI_MODEL` one layer up — env names are now exported from `internal/config` so the two layers cannot drift. **Thoughts now execute**: an event-driven worker pool drains the queue through a `Runner` seam (the shipped `CompletionRunner` makes one provider round trip per thought with no tools; the full agent runner replaces it at the catalog port without the navi's shape changing), the exchange is recorded in the thought's session (one per thought, keyed by thought id — sessions record history, #240), interruption **parks** a thought rather than failing it (the park-not-kill promise), and an empty visible reply is logged rather than treated as a failure since reasoning-capable models spend budget on thinking tokens before emitting text. `WithProvider` overrides resolution, mirroring the daemon's `RuntimeParams.OverrideProvider` seam. Live tests for ollama and openrouter skip cleanly when unavailable, and a hermetic test drives the ollama path against a stand-in daemon so CI covers it on every commit; openrouter was verified live (it replied through the full navi path). New packages and tests; the only change to the existing daemon path is the added `NAVI_PROVIDER`
- Navi composition root (M2, NAVI-343): the public `navi` package — `New` plus `WithVersion`/`WithPersonality`/`WithLogger`/`WithPermissions`/`WithDefaultModel`, and six typed collections (`Skills`, `Tools`, `Models`, `Connectors`, `Portals`, `Modes`) populated during declaration. `Add` does eager shape validation (non-empty metadata, well-formed tool schema, handler present, real access/mode/origin, unique name) and returns an error rather than panicking; `Thoughts` is core and constructed by `New`, never added (ADR 0003); `Run` validates, freezes, assembles, and serves. `Run` re-validates shape and re-checks duplicates so an *ignored* `Add` error cannot reach a serving navi, then applies the cross-cutting checks: mode → tool and mode → model references, portal address conflicts, mode/ceiling permission consistency (ADR 0006 — a mode may narrow by omission, lower its access ceiling, and deny more, but naming a tool the ceiling excludes or raising the access level is rejected), and the ADR 0009 default-model declaration. A component that fails to `Start` aborts the run and everything already started is stopped in reverse. **Contract changes to support it:** `Deps` is now a **lifecycle argument, not a constructor input** — `connector.Connector.Start(ctx, deps)` and `portal.Portal` gains `Start`/`Stop` — because the composition root only assembles `Deps` in `Run`, after every collection is declared, so a component constructed earlier had nothing to receive and no way to obtain the handles it was meant to use (a portal could not even subscribe to the event stream it exists to observe); `thought.Thought` gains `Mode` (ADR 0007) and `portal.Addressed` is an optional capability a portal may implement for port-conflict detection. `runtime.md` reconciled to the shipped contracts, including its `Thought` sketch (it still claimed a `ThoughtStatus` type and a public `Checkpoint` — neither shipped; the checkpoint is scheduler bookkeeping). New package and tests; the `internal/*` runtime is untouched
- Memory model captured (NAVI-350, NAVI-351): `docs/architecture/memory.md` records the two-tier memory design recovered from the retired spec tree — four scopes by ownership (session, user, navi, memories) classified by **load timing** into short-term (always injected into the prompt, per thought, with writes during one thought visible to the next) and long-term (an agent-callable tool that searches the archive and is never loaded wholesale), plus the inter-tier pointer that makes the two a system. Short-term memory is navi-internal — the navi's own working state, not an extension-surface concern — so it is deliberately absent from `connector.Deps`/`portal.Deps`; long-term memory arrives as a tool with the catalog. Also fixes `runtime.md`, which had described the thought system as the navi's "short-term memory" — the queue is not memory, and the occupied name is part of how the original design was lost. Open questions recorded rather than decided: `navi`-scope placement, the write path (is the post-thought pass a runtime step or a tool; can the navi write mid-thought), and pruning policy. Docs only — no code changes

- Memory-first runtime state (NAVI-338): queue mutations are zero-synchronous-I/O in the critical section — mutations mark thoughts dirty (in-memory, under q.mu) and a dirty-set flusher persists them on a 250ms cadence outside the lock (`Config.FlushInterval`; negative keeps the legacy synchronous write-through). Durability-critical points stay synchronous: park-with-checkpoint (the kill-and-lose promise — checkpoint on disk at park time), crash-recovery writes, adoption claims, delete. Loss window documented in the S010002 delta: a kill -9 loses at most one flush interval of non-checkpoint mutations. Flush failures surface as `EventPersistFailed` (metrics persist-failure accounting unchanged), the failed thoughts re-mark dirty, and the queue keeps running. The flusher's stop closure performs a final drain at shutdown
- `navi enqueue` portal-first channel (NAVI-337): with a known portal endpoint (`--portal` flag, then `NAVI_PORTAL` env — resolution order documented in the CLI help) the CLI POSTs the enqueue control action (`POST /portal/control action=enqueue`, identity `cli`, 2s timeout) and confirms on the navi's ack; connection failures and fail-closed 403s fall back to the DB mailbox (the durable path; NAVI-336's reconcile adopts it) with a visible note naming the reason. Provider/model flags ride the DB path until the shim carries them (noted). DB write path intact; S000407 spec note records the CLI control-channel usage
- Store-reconcile loop (S010002 external-writer reconciliation, NAVI-336): the running queue adopts externally-persisted thoughts — `navi enqueue` from another process, cron-from-another-process, any external tool — so external doors reach a running navi (the store is the cross-process channel). `Config.ReconcileInterval` (default 1s, negative disables); adoption mirrors an in-process enqueue — joins pending with the normal slot policy, emits `EventEnqueued` Detail `external-adopted` (TUI/reactive doors see it via the existing refresh path), `DeferUntil` honored for external deferrals (joined pending, skipped until due), failed rows await Retry, externally-written running rows adopt as pending (crash-artifact recovery, same transition recover() makes), terminal rows kept for inspection. Queue-owned rows reconciled to themselves (no duplicate adoption after restart). Q.mu discipline kept (LoadThoughts/emit outside the lock); reconcile cost one LoadThoughts per tick
