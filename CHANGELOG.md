## [Unreleased]

### Added
- Thought live view as a chat window (S000406 delta, NAVI-330): hopping into a running thought now shows the conversation chat-shaped — the thought's Prompt as the opening user turn, assistant deltas accumulated into ONE assistant turn (no per-delta lines), tool calls as indented `⚙` blocks, lifecycle transitions as `·` system lines, and steering deliveries as user turns at their injection point. Tail-follow with scrollback (up/down scroll, windowed history, bounded at 80 turns); rebuild-on-attach renders the snapshot prompt + Context appends and the stream fills in from attach (best-effort window, documented). Presentation only — the portal event stream stays the source of truth; the S000406 spec note records the operator decision that "not a chat REPL" applies to the queue home view, while the live view is a chat-window presentation
### Added
- TUI stdin ownership fix (NAVI-332): `navi run`'s TUI branch no longer spawns the stdin-loop session driver — Bubble Tea owns stdin exclusively (the competing scanner consumed keystrokes and froze the TUI at startup), and `sessionDone` has exactly one closer per mode (the piped-stdin EOF double-close panicked with close-of-closed-channel). `--daemon` stdin loop unchanged. Regression tests: operator repro end-to-end (no panic, no exit-2), daemon clean-drain, structural tripwire against re-adding a stdin reader to the TUI branch
- Docs: corrected the `defaultLogPath` comment in `cmd/navi/run.go` — the default filename is `navi.log`, not navilog (NAVI-331 review)
- TUI log routing (NAVI-331): `navi run` in TUI mode (no `--daemon`) routes the runtime logger to `<db-dir>/navi.log` (JSON, per the file convention) instead of stderr — structured lines no longer scribble over the Bubble Tea alt-screen; a one-time `navi: logs → <path>` line prints before the alt-screen engages so users know where logs went. `--daemon` keeps stderr (its console); explicit `--log-file` is honored in both modes; `--log-format` semantics unchanged (file output stays JSON)
- Shared connector starters (NAVI-325 follow-up to #295): `Runtime.startConnectors` extracts the serve/start sequence — scheduler, metrics listener, portal listener — and `RunForeground` now calls the same starters `Run` uses, so connectors serve in EVERY run mode at the run-path level too (only the foreground-slot reservation stays mode-conditional). Stop closure closes servers first, then the scheduler; the caller's pool drain stays ordered after (the #280/#290 shutdown semantics preserved). Listener failures are logged, not propagated — a headless run without a free port still processes work
- Log-format knob (NAVI-328): `internal/ops/logging` gains the formatter selection — `--log-format human|json` on `navi run` (daemon alias inherits), `logging:{format, level}` runtime-config section (flag wins on conflict per the merge chain; the config is another way to turn the same knobs as the flags), documented default human on an interactive TTY / json otherwise (pipes, redirects, --log-file). JSON output byte-for-byte unchanged for existing callers; spec delta S010104 §7.4 (config-mirrors-flags surface rule) with status history 0.2.2
- Provider/model per thought (S010104, NAVI-327): optional durable `Provider`/`Model` fields on `Thought` (sqlite migration adds the columns; round-trips + crash recovery preserve them — S010002), resolved by the runner when it builds the per-thought agent: thought-level override → runtime primary (+ existing fallback chain when no override is set), with a thought-level `model` override applied on top; **unknown override providers fail the thought with a clear error — no silent fallback**. `navi enqueue` gains `-provider`/`-model` flags; the TUI shows the per-thought model (abbreviated) on each queue row. Spec delta: agent-runtime §13 documents resolution order + fail-loud rule
- TUI enqueue action (S000406, NAVI-326): `n` from the queue home view opens a prompt input (prompt → optional priority 1-10 → optional defer minutes), enqueued through the transport's new `Enqueue` (portal contract unchanged — `Portal.Enqueue` from NAVI-318, no new portal methods) with `Foreground: true` so session-created thoughts claim the foreground slot; the enqueued event rides the same stream, landing the row in the queue view, with ack/rejection display consistent with the other actions. Remote transport posts the shim's enqueue control (`{id, prompt, priority}`; deferral rides along as an ISO field for forward-compat — the current shim ignores unknown fields, so remote deferral is an in-process capability until the shim learns it). `--headless`/`--daemon` stdin loop untouched
- One assembly: connectors in every run mode (S010003/S010104, NAVI-325): `navi run` and `navi daemon` build the SAME runtime — cron scheduler, metrics, and portal connectors load in every mode; the modes differ only by the TUI layer. `navi run` gains `--metrics-addr`/`--portal-addr` (connectors in the binary run too); the foreground slot is reserved only when a session (TUI) is attached — headless runs have no foreground thought (stdin-loop work enters as normal thoughts). `--headless` becomes `--daemon`; `navi daemon` remains as a deprecated alias for `run --daemon` this cycle (deprecation notice on stderr). Human-readable lines kept — structured-log migration explicitly deferred
- Fixed the dead `--ollama-host` flag (NAVI-325): `RuntimeParams.OllamaHost` was declared as a flags-layer override but never applied into `MergeRuntime` — it now sets the flags-layer provider endpoint, so precedence is flag > `OLLAMA_HOST` env > YAML (tested end-to-end through Assemble)
- Bubble Tea TUI portal client (S000406, NAVI-319): `internal/interfaces/tui` — the human door into the house, a terminal UI over the portal surface (queue view home with id/status/priority/age/checkpoint/session-log pointer, seeded from the snapshot and updated live from the mailbox within one event delivery; per-thought actions — attach message / bump priority / pause / resume / cancel / retry — through `Portal` control with delivery acks and rejections displayed; a read-only live view streaming content deltas, tool calls, and transitions with steering as the write path). Transport seam serves in-process (binary run front door; `--headless` keeps the classic stdin loop) and remote (gateway cursor-poll + control POST; fail-closed 403 without an authorizer). **Dependency exception (documented, approved, NAVI-319 only): adds the repo's first third-party dependency, `charmbracelet/bubbletea` (v1.3.10; lipgloss et al. transitives) — the no-new-deps convention stays in force everywhere else; decision + rationale recorded in the thought-loop case study (Open Design Point #4).** **Also — intentional follow-on inside NAVI-319, not scope creep: extends the NAVI-318 portal surface (recorded as a deliberate follow-on, not creep)** with `Portal.BumpPriority`/`Portal.Retry` (authz via new `PortalActBump`/`PortalActRetry`, nil-authorizer fail-closed like every other control) plus the matching `bump`/`retry` serveControl cases, so the TUI per-thought action set stays entirely on the portal contract — never direct queue access. Bump/retry feedback is return-based (priority is not a gauged dimension; Retry emits `EventEnqueued` Detail "retry", which the stream reflects back to `pending`); steer/pause/resume/cancel show their delivery acks on the stream
- Portal observation API + gateway attachment surface (S000407, NAVI-318): the `internal/interfaces` portal contract — a transport-agnostic stream of queue lifecycle events (incl. `EventMessageRouted` delivery acks with their routing path) plus per-thought agent events (content deltas, tool calls, transitions, via a runner hook), bounded slow-consumer-safe subscriber mailboxes (drop-oldest + resumable cursor), and a control channel (attach/steer/pause/resume/cancel/enqueue) with an IAM-aligned `PortalAuthorizer` seam that fails closed when none is wired; the daemon serves the portal on `--portal-addr` (metrics-addr pattern: same listener lifecycle, graceful shutdown), with a loopback-grade JSON shim for live observation and control (wire protocol deferred to 05-messaging). Attachments and control are authorization-gated end to end — observation included, since the stream carries prompt content and tool-input snippets — and fail closed (403) until IAM lands
- `tools/thoughts` — thought-management tools (S130600–130604, NAVI-323): `thoughts_read` (queue snapshot — id/status/priority/prompt summary/timestamps/metadata, optional status filter, priority-then-recency order), `thoughts_create` (prompt/context/metadata/priority + durable `defer_until`; tagged `origin: tool` — the #287 clamp applies at Enqueue and the origin tag is not overridable via caller metadata), `thoughts_update` (priority change clamped to the self-scheduled band, pause/resume/cancel transitions, context append), and `thoughts_delete` (record removal; running thoughts protected — cancel first; terminal records kept for inspection). Registered through the queue-handle seam (`thought.RegisterQueueTools`) with complete S130400 metadata; the queue gains public `Delete` (lifecycle-protected, emits an exact-delta `deleted` event so metrics/portal gauges stay honest) and `AppendContext` methods so all tool mutations flow through queue methods, never GetThought clones
- Binary-run entry + steering bridge (S010003 §06/S010310, NAVI-320): `navi run` drives the same thought queue, pool, and registry-governed tools in-process with no connectors — the interactive session's thought occupies a reserved foreground slot (`RuntimeParams.Foreground` → `Config.ForegroundSlots >= 1`, `MaxConcurrent` bumped to at least 2 so the reservation is expressible); the steering bridge resolves a running thought's in-flight agent (`inFlightAgents` tracker registered by the runner, `agent.Steer` at the turn boundary) and is wired through `Queue.SetSteeringRouter` (invoked outside q.mu per the NAVI-317 contract); stdin lines enqueue durable foreground thoughts or steer the in-flight run via `RouteMessage`; Ctrl+C parks the in-flight thought with its checkpoint (never kill-and-lose — resume via crash recovery); the process exits when the session ends and the queue drains (`Runtime.RunForeground`); no TUI — NAVI-319 attaches over the same runtime
- `internal/thought` defer_until mechanism + queue-handle registration seam (S130600 §00/§02, NAVI-322): `Thought` gains the durable not-before field `DeferUntil` (persisted via a new `thoughts.defer_until` column, crash recovery preserves it — S010002); `Dequeue` skips thoughts until their deferral passes so a deferred entry never blocks due work; `Enqueue` applies the self-scheduled priority clamp for origin-tagged thoughts (`origin: self`/`tool` → conservative band, `EffectiveSelfPriority`); `RegisterQueueTools` binds catalog tools to the navi's own queue handle (per-dispatch `QueueHandle`, same governance as any catalog tool — complete metadata, schema validation, active set, access levels — with snapshot-only reads per the #280 `q.mu` discipline)
- `internal/thought` — queue-level message routing (S010312, NAVI-317): `RouteMessage(id, msg)` delivers by lifecycle state — pending thoughts get a Context append (picked up at claim), running thoughts steer via the agent's turn-boundary steering queue (bridge wired through `SetSteeringRouter`; invoked outside q.mu so bridges may snapshot via `GetThought`), paused thoughts resume (paused → pending) with the message attached to Context and checkpoint intact, and failed/terminal thoughts are rejected with a reason (retry hint for failed per S010002). Every attempt — delivered or rejected, unknown id included — emits a `message_routed` delivery-ack event (`QueueEvent.Delivery` + outcome) so portal clients (S000406) observe delivery and rejections
- Foreground slot reservation (S010003, NAVI-317): `Config.ForegroundSlots` reserves capacity (disjoint from priority slots) claimable only by foreground-tagged thoughts; foreground thoughts prefer their reserved slot, fall back to open slots, and compete by the same priority/preemption rules as daemon work — interactive sessions never starve behind daemon backlog
- Specs (0.2.0, thought-loop): the queue is the navi runtime's main loop in every run mode — house model revises the two-execution-model statement (S010003, S010104); TUI re-spec'd as thought-queue portal with per-thought actions, live thought view, steering, and message granularity (S000406); gateway gains remote portal attachment with authorization (S000407); queue-level message routing by thought id with delivery acknowledgments (S010312). Case study + spec-updates in `docs/case-study/thought-loop/`
- Case study: thought loop — one house, one queue, many doors (TUI/connectors/tools are doors; queue is the runtime's main loop whether daemon or binary run), plus the d3 spec-updates proposal (S010003, S010104, S000406, S000407, S010312) pending approval (`docs/case-study/thought-loop/`)
- `internal/ops/metrics` — thought-queue metrics with Prometheus text exposition (NAVI-258): counters (`thoughts_queued_total`, `thoughts_parked_total`, `thoughts_resumed_total`, `thoughts_preempted_total`, `thought_persist_failures_total`), gauges (`thoughts_in_queue`, `thoughts_by_status{status}`), and a `thought_processing_seconds` histogram (0.1/0.5/1/2.5/5/10/+Inf buckets). Collector rides the `ThoughtQueue.OnEvent` fanout (zero-dep, no client_golang/OTel SDK); in-queue/status gauges are exact lifecycle deltas seeded once from a queue snapshot, so kill-9 → restart recovery is visible at wire time; per-thought breakdown ships as a capped ring gauge (`thought_recent_processing_seconds{thought_id}`, 100-entry FIFO) instead of unbounded per-thought labels on cumulative series. Daemon wires it via `--metrics-addr` (default OFF — zero cost unset), serving `/metrics` through `Runtime.Run` with graceful shutdown; concurrency-tested (parallel scrapes vs event handling)
- Daemon registration of the http tool + `tool_caps` config surface (NAVI-272 wiring): `Assemble` registers `http_request` (SSRF-guarded egress; `AuthResolver` stays nil until S100400 lands, so `authRef` calls fail closed) and a new `tool_caps` runtime-config section tunes the note caps (`max_body_bytes`/`max_navi_bytes`) and http egress (`max_response_bytes`/`allowlist`/`denylist`); the merge chain carries the section (with validation `>= 0`); assembly tests cover cap rejection, denylist enforcement, and the full 9-tool default active set (NAVI-272)
- `tools/http` — stateless `http_request` tool (S130500 §06): CRUD methods (GET/POST/PUT/PATCH/DELETE) returning status, filtered headers, and body; non-2xx responses are normal output; SSRF guard denies private/loopback/link-local/multicast destinations — every DNS-resolved address is checked at validation AND again at dial time via a pinned transport dialer (closes the DNS-rebinding TOCTOU), with per-navi allowlist/denylist (hostname, IP-literal, or CIDR entries), deny-wins precedence, and per-hop redirect re-validation (max 3); `authRef` credential references resolve server-side through the `AuthResolver` interface stub (S100400 planned) and fail closed without one; `Authorization`/`Set-Cookie` echoes stripped from responses; 256 KiB response cap (and method/timeout/cap) configurable per call and via `Options`, with per-call timeout clamped to the 30s definition ceiling (NAVI-271)
- Daemon registration of the time tool (NAVI-272 wiring): `Assemble` registers the stateless `time_read` via `time.RegisterTools`; assembly tests extend dispatch coverage to time_read (IANA zone conversion + invalid-zone error) (NAVI-272)

### Changed
- `tools/time`: embed the IANA tzdata database (`_ "time/tzdata"`) — `time.LoadLocation` previously depended on the host's zoneinfo and would degrade to UTC-only in scratch/minimal containers (CGO_ENABLED=0 daemons included) (NAVI-272)
- `tools/time` — stateless `time_read` tool (S130500 §03): current time in the requested IANA timezone (default UTC until the runtime zone-config lands) as ISO 8601 with UTC offset plus epoch seconds (on by default, `epoch: false` suppresses); invalid zones rejected with an error naming the zone; pure `time` stdlib, registered via plain `registry.Register` (NAVI-269)
- Daemon registration of the note tools (NAVI-272 wiring): `Assemble` registers `note_read`/`note_write` for the navi's identity through the stateful seam (default 64 KiB / 10 MiB caps; per-navi total cap configurable via `note.Options` when a config surface lands); assembly tests extend the end-to-end dispatch coverage to note_write→note_read (NAVI-272)
- Daemon registration of the todo tools (NAVI-272 wiring): `Assemble` registers `todo_read`/`todo_write`/`todo_update` for the navi's identity through the stateful seam (`todo.RegisterTools`, default `--navi-id` scope `default`) and includes them in the default active set; assembly tests verify end-to-end todo_write→todo_read dispatch through the assembled registry (NAVI-272)
- `tools/todo` — durable todo tools per S130500 §00–02: `todo_read` (status filter + limit, ordered by priority then activity), `todo_write` (atomic full-replace returning assigned ids; rollback-on-failure leaves the prior list intact), and `todo_update` (partial updates by id — status/text/priority/remove — with atomic batch rejection on unknown ids). Registered through the stateful storage seam; per-navi persistence via `store.StatefulToolStore` (NAVI-268)
- Daemon tool wiring (S130400, NAVI-272): the daemon assembles a tool registry — builtins (`file_read`, `shell_exec`) register with complete metadata through the new public `tools/builtin` package — and the default active set is composed from the runtime `ToolPolicy` (allowed/blocked lists, per-tool timeout overrides); each thought run's executor is rebuilt from the registry's active set via `tools/bridge`, so the LLM-facing tool surface is registry-governed; `navi daemon` gains `--navi-id` (per-navi scoping key for stateful tool storage) and `navi health` surfaces the navi's todo counts by status (pending/in_progress/done) from the stateful store (NAVI-272)
- `tools/note` — stateful note tools (S130500 §04–05): `note_read` (by id / tag / literal substring, never semantic; over-cap bodies truncated with a notice) and `note_write` (verbatim upsert by id, `remove: true` deletion, 64 KiB per-note and 10 MiB per-navi caps both configurable at registration), registered via `registry.RegisterStateful` with complete metadata (NAVI-270)
- `tools/bridge` — public runtime bridge between the tool registry and the agent runtime (S130400 runtime-integration): binds the registry's active, access-permitted tools into an `agent.ToolExecutor`, applying allowed/blocked policy and per-tool timeout overrides; every call dispatches through `registry.Dispatch` so schema validation and active-set enforcement stay in the registry, and calls are aborted with a timeout error even against ctx-ignoring handlers (NAVI-75)
- Stateful tool storage seam (S130500 §07): `store.StatefulToolStore` contract with per-navi scoping on every method (`ListTodos`/`ReplaceTodos`/`UpdateTodos`/`ReadNotes`/`UpsertNote`/`RemoveNote`), `Todo`/`Note`/`TodoUpdate`/`NoteQuery` types, and `ErrTodoNotFound`/`ErrNoteNotFound` sentinels (NAVI-267)
- `store/sqlite`: migration 6 adds `todos` + `notes` tables keyed `(navi_id, id)` with navi-scoped indexes; `StatefulStore` implementation with transactional full-replace and atomic batch updates (unknown id rejects the whole batch)
- `tools/registry.RegisterStateful` — registration variant binding a per-navi store handle; stateful handlers receive `StateContext{NaviID, Store}` per dispatch; stateless `Register` untouched (NAVI-267)
