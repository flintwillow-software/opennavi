## [Unreleased]

### Added
- ADR 0017 — navi state as typed objects (proposed): portals render the navi through **one surface over declared types** instead of a typed handle per concern. A type is a descriptor over a shared struct (fields with kind/label/section, sensitivity, relations, named detail collections, and **actions** with argument schemas); the composition root registers the types it exposes, exactly like tools/models/skills, so what a portal can see is visible in `main.go`. One surface (`Types`/`List`/`Get`/`Detail`/`Act`/`Watch`) serves the in-process portal and the gateway alike, sensitive fields are omitted by the surface rather than hidden by the portal (keeping ADR 0006/0008 intact), live state arrives as `{type, id, op, fields}` deltas rather than queue/agent event kinds, and **presentation is declared with the type** (view kinds `list`/`detail`/`chat`/`graph`/`board` plus per-field hints, with defaults so hints stay optional) so a portal author implements each view kind once per UI framework instead of writing per-type code — a shipped generic portal toolkit is the renderer, the in-process TUI its first consumer. Introduced now, while the exposed surface is still the navi's own aggregates, so the surface does not have to be retrofitted across a growing component set later. An object type's source is the view its component was bound to — per-type binding, with the datastore's per-aggregate routing as the single-backend default, so mixing backends (todos on `fs`, notes on `postgresql`) stays one rule — the surface is RAM-first and serves live values from memory even with no datastore, and the type is the top-level namespace (`GET /{type}/{id}/{detail}`, with `/_types`/`/_deltas` kept out of the type root). Settles what ADR 0012's snapshot carries; the wire framing, IAM placement, query shape, and type versioning remain open. Docs only — no code changes; supersedes the NAVI-361 typed-history shape as the end state
- The `sqlite` datastore backend (NAVI-364): the contract's single-file, transactional option — `datastore/sqlite` now implements `datastore.Backend` (thought/transcript, tool-state, and memory views) instead of the retired session-CRUD interface, and is selectable with `datastore.backend: sqlite` (`fs` stays the **compiled default**; `inmem` stays the non-durable reference). The reference navi declares it, rooted at the same database the cross-process mailbox and cron tick state already use. A thought's transcript is keyed by thought id and written as a unit; `TranscriptInfo` answers from a metadata projection (`thought_transcript_meta`) so enumerating thoughts or transcript metadata selects **no message body** — the property the shared conformance suite proves through `conformance.ReadReporter`, which the backend now implements. The backend is configured for the datastore's one ordered writer: WAL plus a busy timeout, so a flush never blocks a read and a second process sharing the file waits rather than fails. Transcript message bodies and tool input are encrypted when `NAVI_SESSION_KEY` is set (the cipher seam is kept and now actually wired); memory and notes stay plaintext because recall and note search match them with literal substrings. Migrations are append-only: an existing `navi.db` is upgraded in place — thought rows survive and the retired `sessions`/`messages` tables are left untouched — never half-read. New `templates/navi-sqlite` shows a navi whose whole state lives in one file. The backend runs the shared conformance suite in CI, and its own tests cover candidate selection, WAL, body-free metadata reads, transcript encryption, an empty transcript, and reopen-without-loss
- The `fs` datastore backend (NAVI-365): the navi's state as a directory tree a person can read, diff, and back up with ordinary tools — and the step that ends the volatility. `fs` is now the **compiled default** (ADR 0011), so the reference navi's transcripts, tool state, and memory survive a restart; `inmem` stays declared as the non-durable reference, selectable with `datastore.backend: inmem`. Layout under one per-navi root (`datastore.params.path`, required — the backend fails loudly rather than guessing a location): `thoughts/<thoughtID>/thought.md` (frontmatter is the thought row, including `depends_on`, skills, the assembled context, a base64 checkpoint, and the transcript's message count and update time; the **body is the transcript**, rendered as a readable conversation with one marker comment per entry), `todos/<naviID>/manifest.md` + `todos/<naviID>/<todoID>.md` (the manifest is the batch's atomic anchor, written last, so a rejected or interrupted batch leaves the previous list authoritative), `notes/<naviID>/<noteID>.md`, and `memory/<scope>/<id>.md`. Two properties are structural: **metadata without bodies** — enumeration reads frontmatter only (the reader stops at the closing delimiter, and `TranscriptInfo` answers from stored metadata), which the conformance suite checks because this backend implements `conformance.ReadReporter`; and **atomicity** — every write is temp-file + rename, so a reader never sees a half-written file and a failed write leaves the previous one in place. `Open` takes an advisory lock on `<root>/.lock`, so two processes on one root fail loudly instead of silently interleaving. The backend runs the shared conformance suite in CI, and its own tests cover readability, enumeration-without-bodies, restart read-back, root exclusivity, manifest anchoring, and failed-write atomicity. `cmd/navi` declares both candidates and roots `fs` at `<db-dir>/state` (`var/data/state`), which a `datastore.params.path` in runtime config overrides; `inmem.Candidate()` is no longer marked default (exactly one candidate may be). Bounded/cursor transcript reads are deliberately not here — the contract has no paged read (see NAVI-376's scoping note)
- Backend conformance suite (NAVI-376): the datastore contract now ships its own **shared conformance suite** (`datastore/conformance`), so a backend is provable rather than plausible. One entry point (`conformance.Run(t, open)`) plus per-aggregate entry points assert the behaviour a consumer depends on: thought round-trip across every durable field (including `DependsOn`, `Skills`, `Assembled`, checkpoint and metadata), transcripts written as a unit with entry order and tool-call fields preserved and `TranscriptInfo` agreeing with the body, tool state (todo replace and all-or-nothing update batches, notes verbatim, **per-navi scoping**), memory (recall filters, most-relevant-first ordering, expiry **carried not interpreted**), documented failures returning wrapped sentinels rather than silent success, caller memory never aliased, and concurrent readers never blocked or failed by an in-flight write. The suite belongs to the contract, not to the in-repo backends: `internal/testdata/external-backend` is a synthetic out-of-repo backend module that imports and runs it in CI, and the `external-consumer` guard now checks that fixture's boundary — including its **test-only** imports, where the suite is imported — exactly as it checks a third-party author's. "Metadata without bodies" is *proven* rather than asserted: an optional `conformance.ReadReporter` lets a backend report transcript body reads, the reference backend implements it, and a backend that does not is reported as **unverified** instead of passing silently. `datastore/inmem`'s aggregate round-trips moved into the suite, leaving only what is specific to the in-memory backend. Two items the issue named are deliberately **not** invented here because the contract has no such surface: a cursor/limit transcript read (the suite asserts the metadata/body split that exists, and a cursor read belongs to NAVI-361/364) and a capability-reporting API for prunable things (sentinels and assembly-time validation are what exist today, and NAVI-363 is where the capability surface lands) — both recorded as open questions on the issue. `runtime.md`, `overview.md`, and `memory.md` reconciled
- Plan closing checks (NAVI-379, ADR 0016): a plan of thoughts is no longer done when its last stage completes. `core_thoughts` now tells the model to close a multi-stage plan with a **verification thought** — `depends_on` set to the stage it checks, metadata `role: verification` — carrying a concrete check of the result (run it, read it back, diff it) rather than another implementation step. The **runtime guarantees it**: when a plan drains with no check behind it, the navi queues one itself (`navi.WithPlanCloseCheck`, on by default). The rule is mechanical rather than heuristic: the plan is the dependency-connected component of the completed thought (NAVI-378's graph — no plan object), every member must be `complete` (a failed or cancelled stage means the plan did not succeed, and its dependents were already failed), a plan containing a verification is left alone so a check never spawns another, and the synthesized check depends on the plan's **sinks** — so parallel branches are covered — with an id derived from those sinks so a replayed event or a restart cannot queue a duplicate. A standalone thought is not a plan and is not closed. New public graph helpers `thought.Plan`/`thought.PlanSinks`/`thought.PlanSucceeded`, the `thought.RoleVerification`/`MetadataRole` vocabulary with `Thought.IsVerification`, a `V` flag on the TUI row, and `thoughts_create` guidance for the model's own closing check. ADR 0016 is the design record and `runtime.md` gains a *Closing a plan* section
- Thought dependencies (NAVI-378): a plan of thoughts can now keep its order. `thought.Thought` gains `DependsOn []string` — the ids this thought waits on — persisted with the row (`depends_on`, migration 15) and copied by `Clone`. `Queue.Dequeue` refuses to claim a pending thought until every dependency has reached `complete`, so a later stage cannot start before its predecessor **with more than one worker and with preemption in play** (a paused dependency is not complete — preempting a chain's head parks the chain). There is **no new lifecycle status**: "blocked" is derived for display (`thought.UnmetDependencies`, surfaced as `blocked_by` on the thought tool view and `blocked` in the TUI row), so the scheduler and the record keep one vocabulary. A dependency that fails, is cancelled, or is removed fails its pending dependents transitively with a detail naming the dependency (`pending → failed` joins the transition matrix, so a dependent is retryable; `Retry` re-applies the gate), and a graph loaded with an already-dead dependency settles the same way at recovery and external adoption. `Enqueue` validates at the door — every id must already exist, self-dependency is rejected, and an edge that would close a cycle is refused — which together with unique ids makes an in-process graph acyclic by construction. `thoughts_create` takes `depends_on` and returns the created id, so the model chains a plan by naming the ids it just created ("this continues `t1`"). ADR 0015 is the design record and `runtime.md` gains a thought-dependencies section. Additive state-machine and ABI change — `Semver: minor`
- Thought context assembly (NAVI-368): context is now assembled **at thought creation** and carried by the thought. `thought.Queue.SetAssembler` is the seam — the composition root installs its assembler on the queue it owns, so every enqueue path assembles once, at the door, and a thought that cannot be assembled (an unknown declared skill) is rejected at `Enqueue` rather than mid-run. The assembled block (personality, mode fragment, loaded skills, short-term memory) is persisted on the row (`Thought.Assembled`, migration 13; declared `Skills` alongside it, migration 14), the runner consumes it instead of rebuilding per turn, and it is recorded as the thought's **first transcript entry** (index 0) so it is readable through the same contract as the rest of the transcript. Assembly is build-time-only and reproducible, and it truncates past the navi's budget with a reported marker (`WithThoughtBudget`, default 16k). The **deferral trigger** ships: as a run approaches its budget the agent loop injects one notice telling it to finish a coherent unit, write the handoff with `memory_write`, and queue follow-ups with `thoughts_create` declaring their skills. A successor inherits only what short-term memory carries
- Core skills (NAVI-372): `n.Skills` is now read. The runtime generates a core skill for each component type the navi actually declares — authored prose for semantics (`skill.CoreTools()`, `CoreThoughts()`, `CoreConnectors()`, …) — plus a mechanical `core_inventory` derived from component metadata, so the model is never unaware of a capability the binary has. All three loading paths of ADR 0013 decision 5 now exist and resolve against the compiled-in set only: author-declared auto-load (`skill.Skill.AutoLoad`), a thought's declared request (`thought.Thought.Skills`, settable through `thoughts_create`), and the agent-chosen `skill_load` tool (`n.SkillTool()`, added explicitly like any other tool). A request for an unknown skill fails the thought rather than fetching anything, and `core_` is a reserved namespace. The auto-loaded core set is bounded by the declared component types and measured (~300 tokens for a 7-tool navi, pinned by `TestInventoryTokenCost`); `cmd/navi` adds the skill tool
- Short-term memory (NAVI-351): the always-loaded tier of the memory model (ADR 0013) ships as a navi-internal service (`internal/memory`) — `user` and `session` notes held in RAM, hydrated once at assembly from the datastore's memory view, injected into **every** thought's system prompt so no tool call is needed, and written back through the ordered writer. `navi.WithShortTermMemory()` declares it, and the runtime registers the built-in `memory_write` tool (add/replace/remove, `user` or `session` scope) as the deliberate write surface — kept navi-internal rather than published as a `tool/memory` component package, so an out-of-repo module cannot reach it. A note written during thought *N* is visible to thought *N+1* immediately (it lands in RAM, not only on flush). Declaring memory with no datastore candidate fails at `Run` with a clear error rather than silently keeping memory volatile. The `navi` and `memories` scopes stay with long-term memory (NAVI-350); metadata-first hydration and retention are deferred (NAVI-377/NAVI-363). `cmd/navi` enables it
- Context assembly and connector scope (ADR 0013, ADR 0014): the **thought queue is the context mechanism**. Context pressure is resolved by bounding thoughts and deferring work into follow-up thoughts — a thought approaching its budget finishes a coherent unit, writes what the next one needs into short-term memory, and queues follow-ups declaring which skills to load — rather than by compacting a long conversation, which is why **compaction is being removed** instead of kept as a fallback. Context is assembled **at thought creation**, not per turn, and the assembled context is recorded as the thought's first transcript entry so it is readable through the same contract as the rest of the transcript. Everything that shapes context is a **build-time declaration** — sources, auto-loaded skills, component-derived guidance — because if a prompt can reach the assembler then the assembler is an injection surface; runtime config may only narrow it. **Skills are loaded selectively** through three paths (author-declared auto-load, thought-declared request recorded when the thought is queued, agent-chosen tool), all restricted to the compiled-in set, so a manipulated request can at worst load a skill the author already shipped. Core skills ship with the component types: authored prose for semantics plus a mechanical inventory derived from component metadata, so the model is never unaware of a capability the binary has. Separately, **connectors are redefined as bidirectional service integrations**, amending ADR 0010's "inbound only" wording: inbound they turn external stimuli into thoughts, outbound they supply the tools that act on that service via `connector.SendTool()`, added explicitly and never auto-registered. Egress payloads are service-specific, so there is **no generic webhook schema**, and role separation between navis is **structural** — a function of which components and tools exist in a binary, not of what a prompt says. `runtime.md` (new context-assembly section, rewritten connector bullet), `security.md` (new *Context and the injection boundary* and *Egress* sections), `memory.md` (short-term memory as the inter-thought carrier, now on the critical path), and `overview.md` reconciled. Docs only — no code changes; the compaction removal is tracked separately. Delivery: NAVI-368 (context assembly) and the connector/egress issues under epic NAVI-362
- Persistence and portal-stream design (ADR 0011, ADR 0012): persistence becomes a selectable `datastore` **component** and RAM is the source of truth at runtime. The store leaves the read path — metadata loads eagerly at cold start while transcript detail loads on access and is garbage-collectable, transcript writes are asynchronous per message, and one globally ordered writer batches on flush so a crash leaves a *prefix* of history rather than a per-aggregate patchwork. Consumers depend on **per-aggregate views** (thought/transcript, tool state, memory) and the collection routes aggregate → active backend, defaulting every aggregate to the single active datastore — so multi-backend is a config change rather than an ABI change. `store` is renamed to `datastore` and its session-CRUD interface is **deleted rather than carried forward**; tools and memory are datastore consumers, and both memory tiers require a configured datastore; retention defaults to unbounded behind an explicit prune mechanism. ADR 0012 (proposed) replaces the separate observation and control surfaces with **one bidirectional navi stream** a portal translates for its transport, opened with a bounded state snapshot, with read vs write decided by IAM scope per portal. `runtime.md`, `overview.md`, `memory.md`, and `extension-model.md` reconciled. ADR 0010 stands: a datastore sits *beneath* the thought system and is a new component kind, not a fourth capability layer. Docs only — no code changes. Delivery is tracked under epic NAVI-362: NAVI-360 (datastore component + integration surface, including the shared backend conformance suite), NAVI-365/NAVI-364/NAVI-367 (`fs`/`sqlite`/`postgresql` backends), NAVI-366 (per-aggregate routing), NAVI-363 (explicit prune), and NAVI-361 (portal consumption), with NAVI-353 reduced to the design record
- M6 — synthetic out-of-repo CI modules (NAVI-346): `tools/external-component` is its own module publishing a tool, a connector, and a fail-closed portal that import **only** the public contract packages (`tool`, `thought`, `connector`, `portal`, `model`, `skill`), and `tools/external-navi` is its own module composing the public `navi` root over that component and validating it. The CI guardrail builds and runs both and asserts the component's import boundary — its direct imports must be public contract packages, and its dependency closure must not reach `navi` or `internal/` — so an extension author outside this repository provably needs nothing but the public surface
- M5 — the reference navi and the starter templates (NAVI-347). `cmd/navi run` now assembles through `navi.New` instead of `internal/daemon.Assemble`: the reference navi builds durable stores, the full catalog, configured providers (with the ADR 0009 fallback chain and `--compact-budget` compaction), the cron connector, and its portals, then calls `navi.Run`. `enqueue`/`health` are unchanged; daemon mode additionally serves the HTTP portal gateway, and the gateway is now a real control surface — the public `portal.Control` + `portal.Authorizer` let remote front-ends attach, observe, and control (queue, steer, pause/resume/cancel, bump, retry) across processes. `portal/tui` is public and `internal/portal/cli` (the legacy REPL) is deleted: the default command runs the navi (TUI, or headless with `--daemon`). `navi-code` and `navi-daemon` are converted to real `navi.New` modules (no `sdk.Build`). NAVI-353 tracks transcript replay/restore across all portals; NAVI-354 tracks the daemon-run-path cleanup

### Removed
- Context compaction is retired (NAVI-370): `internal/context` (budget/compact/counter), `internal/agent/compaction.go` and its `maybeCompact` loop step, `AgentConfig.Compaction`/`CompactionConfig`, `navi.WithCompactBudget`, and `cmd/navi`'s `--compact-budget` flag are deleted, and the vestigial `messages.is_compacted` column and its index are dropped by migration 11. It was already off by default, so nothing changes at runtime — the machinery went so the shipped surface stops advertising an approach the architecture rejects. This is not a lost capability: ADR 0013 makes the thought queue the context mechanism, so context pressure is resolved by **deferral** into follow-up thoughts (a bounded unit, a short-term-memory handoff, successors that declare their skills) rather than by compacting a long conversation
- M5 cleanup — the dead daemon run path (NAVI-354): `internal/daemon` (`Assemble`/`Run`/`RunForeground`, `AgentRunner`, `WireCron`, `WireLogging`, `PortalHandler`, and their tests) and the `internal/portal` alias shim over the public `portal` types are deleted. Production no longer imported either — `cmd/navi run` assembles through `navi.New`, and `navi/` already owns the runner/registry/runtime helpers — so the daemon package survived only as a test fixture. The tests that leaned on `daemon.Assemble` (`portal/tui`, `portal/gateway`, `cmd/navi`) now build the minimal public surface directly (`thought.NewQueue` + `portal.NewControl` + `portal.NewBroker` + `gateway.Handler`), which is smaller than the assembly it replaced; the navi catalog-parity test keeps its 13-tool default-active-set assertion without the deleted reference. `internal/config` and `internal/ops/logging` stay internal (they are live: the public navi reads the runtime file by path, so the YAML is not duplicated per navi); the thought-queue metrics collector (`internal/ops/metrics`) loses its only consumer and stays parked pending wiring onto the reference navi (NAVI-357). The same sweep found that the daemon's `WireCron` was the only caller of cron tick-state persistence (`MigrateState`/`StateStore`/`RecordFire`/`MissedTick`), so the reference navi has run schedules without `last_fired`/`fire_count` or missed-tick coalescing since M5 — tracked as NAVI-358. Docs (`overview.md`, `memory.md`, `README.md`) reconciled

### Fixed
- The closing check could fire on a partial plan (NAVI-382): a navi stages a plan one stage at a time — `thoughts_create` returns the id the next stage names — so between two calls the queue can be momentarily *drained* (every thought complete, the next stage not yet enqueued) and the runtime closed the partial plan. Two consequences, both real: a **premature check** verified a stage the plan no longer ended at — exactly the "a check that does not check the real result" failure ADR 0016 exists to prevent — and because synthesis skipped any plan that already contained a verification, the **extended plan never got a proper check** (the same hole covered a plan deliberately extended after it drained). The skip condition is now "the plan's sink set is not already closed" rather than "the plan contains no verification": a verification is a check, not a stage, so it no longer counts toward the plan's shape (success and sinks are read from the stages alone), and a plan is already checked only when a verification depends on **exactly the current sinks**. When the plan grows past an earlier check, its successor is queued — and the superseded check, if it has not started, is cancelled first (`Queue.Cancel`; a check the model queued itself is left alone, and a check that already ran is kept). A verification is never re-closed (no check of a check), a standalone thought is still not a plan, and the synthesized id still derives from the sinks, so a replayed event or a restart cannot queue a duplicate. Tests: the incremental case is staged with **no gate on the plan's stages** — stage 1 completes before stage 2 is enqueued — and pins both the final-sink check and the cancellation of the superseded pending one; a plan extended after it drained gets a fresh check while the completed superseded one is kept
- The queue's event fanout now meets its own contract (NAVI-67): `emit` documents that it MUST run without `q.mu` held, because an observer may re-enter the queue — but `PauseWithCheckpoint`, `Resume`, `Complete`, and `Retry` still dispatched handlers while holding the lock, so any observer that read a thought from one of those events (`GetThought`/`GetThoughts`) deadlocked the queue. Reproduced with a re-entrant observer on `EventCompleted` (`Complete` → `emit` → `GetThoughts` blocking on the mutex `Complete` still held). All four now follow the collect-under-lock / emit-after-unlock pattern the rest of the queue uses (`Fail` and `Cancel` were converted in NAVI-378), so the documented guarantee is true again. The regression test drives every emitting transition — enqueue, dequeue, complete, pause, resume, fail, retry, cancel, delete — with an observer that re-enters the queue, each on its own queue, and names the transition if one deadlocks. Beyond event timing (an event now fires after the lock is released rather than while it is held) there is no behaviour change
- The live chat view still duplicated its events (NAVI-381): NAVI-380 fixed the cursor *write*, but every `Update` path re-armed the feed drain, so a key press (or `WindowSizeMsg`) stacked a second `tea.Every` timer while the previous one was still in flight. The mailbox read is non-destructive (a bounded replay ring), so N stacked timers each read the same range and each applied it, and a stale timer's captured cursor let the model's cursor move *backwards*; the chat showed each event once per in-flight timer — `ALPHA`, the run's system lines, `ALPHA` again, and so on. The drain is now single-flight (`tuiModel.polling`; re-arming while one is armed is a no-op), the idle-stop decision moved into `Update` (the poll command always returns a possibly-empty `feedMsg`, and `Update` stops the drain only when the mailbox was genuinely empty and nothing is running, preserving the NAVI-335 idle-free tick without a command goroutine touching the model; `tickMsg` is removed), and `Update` applies only events past the consumer cursor and never moves it backwards, so a duplicate delivery of an applied batch is ignored rather than re-appended. Regression tests: a duplicated batch no longer re-appends its turns (fails against the unfixed code), re-arming while a drain is in flight is a no-op, and an idle read still stops the drain
- The live chat view (NAVI-380): streaming deltas were duplicated (`NowNowNowNow…`) because the TUI advanced its feed cursor inside a `tea.Cmd` goroutine — a write that races and can be lost, so already-applied events were re-read and re-appended. The cursor now advances in `Update`, carried on the batch. Content deltas also lost their inter-token spacing (`I'llrun`) because `agentDetail` trimmed every fragment; a delta is now preserved verbatim and only whole messages are trimmed. And a tool result rendered as the tool's *input* JSON rather than its output because `agentDetail` ignored `ToolUpdate.Result`; results now report the output and mark errors
- Cron schedules lost their tick state and missed work across restarts (NAVI-358): the retired `internal/daemon.WireCron` was the only caller of `internal/cron`'s `MigrateState`/`StateStore`/`RecordFire`/`MissedTick`, so since M5 the reference navi ran schedules with no persisted `last_fired`/`fire_count` and *skipped* — rather than coalesced — a tick that came due while it was down. `connector/cron` gains a `WithStateStore(db)` option: `Start` migrates the `schedule_state` table, records a fire on every schedule thought's `EventStarted`, and coalesces each overdue schedule into one `missed: true` thought before the scheduler starts. `cmd/navi` passes its store, so the reference navi persists tick state again. `MissedTick`'s thought id now carries the scheduler's monotonic counter, so a coalescing tick and a live `fireNow` landing in the same wall second no longer collide; and the now-dead `config.CronConfig.ToSchedulerDefs` (no callers after the daemon retirement, and the only reason `internal/config` imported `internal/cron`) is removed. `WithStateStore` is optional — an in-memory-only connector behaves as before
- M6 — the `sdk/` authoring stub (NAVI-346): `sdk.NaviDef` and `sdk.Build` are deleted now that the `navi` object owns authoring (M5), and the synthetic `tools/sdk-consumer` module that imported them is retired. Its replacement keeps a distinct CI check: the `templates` job (S000805 guardrail) is unchanged, and a new `external-consumer` job builds and runs the two external modules and asserts the component's import boundary

### Changed
- Repo hygiene after the `fs` default (NAVI-365): the backend roots state at `<db-dir>/state`, so running the reference navi from the repo root with the default `-db ./navi.db` writes `./state`. That directory is now gitignored alongside `/navi.db` and `/navi.log`, so a plain `navi run` no longer dirties the tree (pass an explicit `-db var/data/navi.db`, or use `just daemon`, to keep everything under `var/`)
- RAM-first runtime write path (NAVI-374): the datastore gains a single serialized, globally ordered **writer**. Producers stage writes on it — the thought queue's flusher, the thought/transcript view, and stateful tool state — and it coalesces per key so a burst collapses to one write, drains outside the producers' path, and **re-queues a failed write** rather than dropping it, surfacing the failure through `WriterConfig.OnError` (the navi logs it). A producer never blocks the backend, so a stalled backend can no longer block a run or a lifecycle transition (tested). Transcripts stop writing synchronously at run end: `AgentRunner` stages them on the writer, so a run never waits on disk and a hard kill may lose the unflushed tail (the documented loss window). The `thought.Store` interface is unchanged — the queue's flusher prefers an optional non-blocking `EnqueueThought` and falls back to `SaveThought` — and the navi adapts `thought.Store` onto the datastore (`datastoreThoughtStore`), keeping the queue memory-first while routing its writes through the one writer; the queue is built before the datastore binds, so it falls back in-memory until then and the runtime re-runs recovery (`thought.Queue.Recover`) at assembly. The navi's default queue cadence becomes the async dirty-set flusher, since a synchronous write-through under `q.mu` would now block a lifecycle transition on a slow backend. Fixes a checkpoint bug: the worker parked with `Pause` (nil checkpoint) instead of `PauseWithCheckpoint`, so an interrupted thought resumed from scratch — it now resumes from the runner's snapshot (tested). Metadata-eager/detail-lazy hydration and the `weak` GC moved to **NAVI-377**; the memory-requires-a-datastore assembly check lands with **NAVI-351**
- The datastore contract (NAVI-375): `store` is renamed to `datastore` and its session-CRUD interface and model (`Store`, `Session`, `LoadSession`/`SaveSession`/`ListSessions`, the branching/label/fork fields, compaction helpers) are **deleted rather than carried forward**. `datastore` is now the public persistence contract: per-aggregate views (thought/transcript, tool state, memory), a `Candidate`/`Backend` set declared like providers (ADR 0009), and a stable `*Datastore` handle that is a set of views rather than a backend — so a navi declares its candidates at build time (`n.Datastores.Add(inmem.Candidate())`) and selects the active one at runtime from the new `datastore:` config section, and retargeting storage is config rather than an ABI change. Registration validates shape, assembly validates binding: naming an uncompiled backend, or holding a view with no candidate to bind to, fails at `Run` with a clear error. Multi-backend routing ships as a validated seam (NAVI-366).
